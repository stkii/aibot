# スレッドでの会話

新しい実装は `python -m src.aibot` で起動する。
起動時に使用量・上限設定・会話スレッドの登録用テーブルを作成し、コマンドを登録する。

- サーバーのテキストチャンネルで `/talk` を実行すると質問の入力画面が開く。
- 質問を送信すると、チャンネルに質問を表示して公開スレッドを作り、その中に最初の返答を送る。
- 以降はスレッド内にそのまま投稿すると会話を続けられる。旧実装と同じく、作成者の投稿だけに返答する。
- `/talk` で作ったスレッドと作成者は `aibot.db` に保存し、再起動後も利用する。無関係なスレッドでは返答しない。
- 通常のチャンネル・DM・botの投稿・文章のない投稿には返答しない。
- 会話履歴は `talk:<スレッドID>` ごとに `agent_sessions.db` に保存する。スレッドが違えば履歴も分かれる。
- 同じスレッドの返答は、使用量の記録とDiscordへの送信が終わるまで順番待ちする。
- 同じユーザーの別スレッドへの投稿も順番待ちする。この制御はbotを1プロセスで動かす前提。
- 管理者権限のあるメンバーは上限判定を免除する。使用量は管理者も記録する。
- `/forget` は会話スレッド内で作成者だけが実行できる。進行中の返答を待ち、そのスレッドのAIの会話履歴を消去する。Discord上の投稿・トークン使用量・スレッド登録は残る。
- `/limit` で自分の使用量を確認できる。
- 管理者は `/set-limit limit:10000` で全体の既定値を変更できる。`user` を指定すると個別設定になる。
- AI実行前の累計が上限以上なら停止する。1回の返答で上限を超える場合はある。
- 履歴の自動削除・自動要約・取得件数制限は行わない。

Discord側でMessage Content Intentを有効にし、対象チャンネルの閲覧・送信・公開スレッド作成と、スレッド内の送信権限をbotに与える。
`DISCORD_TOKEN`、`OPENAI_API_KEY` と `resources/agents.yml` の設定が必要。

スレッド作成にはdiscord.pyの[メッセージからのスレッド作成](https://discordpy.readthedocs.io/en/stable/api.html#discord.Message.create_thread)を使用する。
